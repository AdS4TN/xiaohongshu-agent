# AI/科技热点短文网站验收标准

## 1. 核心验收目标

网站每天获取公开科技热点，并为每个热点生成一篇客观短文。

核心验收结果：

- 首页能看到热点列表。
- 每个热点都能点进详情页。
- 详情页展示的是短文，不是字段堆砌或报告式分析。
- 每篇短文保留相关来源。
- C 层深度研究/资料补充能力可触发。

---

## 2. 内容验收标准

### 2.1 首页卡片

每张卡片必须包含：

- 标题
- 一句话摘要
- 类型标签
- 来源标签
- 详情入口

不得只展示原始 API 字段。

### 2.2 单热点文章

单热点文章必须满足：

- 有文章标题
- 有自然段正文
- 正文长度不应过短
- 内容以事实描述为主
- 说明热点是什么
- 说明它为什么会成为热点
- 保留相关来源

不得出现：

- “结论 / 关键事实 / 影响面 / 客观分析”这类报告式字段堆砌
- 纯列表代替正文
- 主观劝导式结论
- 无来源的事实扩写

### 2.3 C 层深度研究

C 层必须满足：

- 每个热点详情页有触发入口
- 触发后能进入 running / success / cached 状态之一
- 成功结果可以被缓存
- 已有成功结果时不重复生成

---

## 3. 功能验收标准

### 3.1 手动采集

点击“手动采集”后：

- 系统启动采集任务
- 不应阻塞页面访问
- 采集完成后热点列表可刷新

### 3.2 刷新热点文章

点击“刷新热点文章”后：

- 系统为当前热点重新生成文章
- 首页和详情页读取新缓存
- 失败时应给出错误提示

### 3.3 来源查看

每个详情页右侧必须展示相关来源列表。

---

## 4. 自动化验收

可执行：

```bash
python -m compileall app scripts
python scripts/smoke_acceptance.py
```

通过标准：

- 编译无错误
- smoke 脚本输出 `status: passed`
- 热点数量大于 0
- 至少一个热点详情包含 `article_title` 和 `article_content`
- 文章正文不是报告式字段
- 来源数量大于 0

---

## 5. 人工验收

打开：

```text
http://127.0.0.1:8000/
```

检查：

1. 首页是否展示热点卡片。
2. 点击任意热点是否进入文章详情页。
3. 详情页是否是一篇短文。
4. 右侧是否有相关来源。
5. 点击“AI 深度研究”是否能触发 C 层任务。
